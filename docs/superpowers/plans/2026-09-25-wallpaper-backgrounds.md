# Pluggable Wallpaper Backgrounds Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the user choose, in Settings, where the app's background wallpaper comes from — their own Immich library (default) or a free external photo service with a real API (Pexels, Unsplash) — and show it behind the Albums and Settings screens in both shells.

**Architecture:** A new `core/wallpaper.js` holds a provider registry (`immich`, `pexels`, `unsplash`); each provider is `{id, label, needsKey, fetchRandom(apiKey, deps) -> Promise<{url, credit}>}`. The same file exposes `createWallpaperService({settings, client, http, debugLog, random})` with a single `refresh() -> Promise<url|null>` that picks the configured provider, never rejects, and logs through `core.debugLog`. `core/settings.js` persists `wallpaperEnabled`, `wallpaperProvider` and a per-provider key map. Each shell owns a tiny applier that preloads the image with `new Image()` and then sets a `background-image` with a dark gradient overlay, plus a 10-minute refresh timer started when the Albums screen is entered.

**Tech Stack:** ES5 JavaScript (`core/`, `shell-legacy/`), `node --test`, ESLint 9 (`ecmaVersion: 5`), `tools/check-es5.js` Chromium-38 gate, React 18 + `@enact/sandstone` 2.9.13 (`shell-enact/`).

**Spec:** `docs/superpowers/specs/2026-09-25-next-features-design.md` (approved design overview — Unit 5 section) and `docs/superpowers/specs/2026-09-18-immich-webos-tv-design.md`

## Verified provider facts (checked 2026-09-25; do not re-guess these)

| Fact | Value | Source |
|---|---|---|
| Pexels search endpoint | `GET https://api.pexels.com/v1/search` with `query` (required), `orientation` = `landscape\|portrait\|square`, `size` = `large(24MP)\|medium(12MP)\|small(4MP)`, `page` (default 1), `per_page` (default 15, max 80) | https://www.pexels.com/api/documentation/ |
| Pexels curated endpoint | `GET https://api.pexels.com/v1/curated` — `page`, `per_page` only, **no `orientation`**, which is why this plan uses `/v1/search` | same |
| Pexels auth | `Authorization: YOUR_API_KEY` (raw key, no scheme) | same |
| Pexels response | `{photos: [...], page, per_page, total_results, next_page, prev_page}`; each photo has `id, width, height, url, photographer, photographer_url, photographer_id, avg_color, alt, src` | same |
| Pexels `src.large2x` | "The image resized `W 940px X H 650px` `DPR 2`" = 1880x1300 — the best fit for 1920x1080. (`src.landscape` is only 1200x627.) | same |
| Pexels rate limit | 200 requests/hour, 20,000/month | same |
| Unsplash random endpoint | `GET https://api.unsplash.com/photos/random`, params `collections, topics, username, query, orientation, content_filter` (default `low`), `count` (default 1, max 30) | https://unsplash.com/documentation |
| Unsplash `orientation` values | `landscape`, `portrait`, `squarish` | same |
| Unsplash auth | `Authorization: Client-ID YOUR_ACCESS_KEY` | same |
| Unsplash response shape | **without** `count`: a single photo object; **with** `count`: an array. This plan omits `count`. | same |
| Unsplash `urls` keys | `raw` (base URL + `ixid`, meant for adding your own parameters), `full` (max dimensions), `regular` (1080px wide), `small` (400px), `thumb` (200px) | same |
| Unsplash resizing | "Dynamically resizable images": append `w`, `h`, `fit`, `q`, `fm`, `dpr`, `auto=format`, `crop` to the `raw` URL. This plan uses `w=1920&h=1080&fit=crop&q=80&fm=jpg`. `regular` (1080px) is too small for a 1920-wide TV and `full` can be a 6000px JPEG. | same |
| Unsplash rate limit | 50 requests/hour in demo mode, 1000/hour once approved | same |
| Pexels CORS | Live check: `GET` returns `access-control-allow-origin: *`; preflight `OPTIONS` with `Access-Control-Request-Headers: authorization` returns `200` with `access-control-allow-headers: authorization`, `access-control-allow-methods: GET, POST, PUT, PATCH, DELETE, OPTIONS, HEAD` | live `curl -D -` with `Origin: null`, 2026-09-25 |
| Unsplash CORS | Live check: `GET` returns `access-control-allow-origin: *`; preflight returns `200` with `access-control-allow-headers: authorization`, `access-control-allow-methods: GET, POST, PUT, DELETE, OPTIONS` | same |
| **Wallhaven CORS** | Live check: `GET https://wallhaven.cc/api/v1/search` returns `HTTP/2 200` with **no `access-control-allow-origin` header at all**. A `file://`-origin TV app cannot read the response. **Wallhaven is not implemented**; it is documented as future work needing a relay this project deliberately does not have. | same |

Both external calls send an `Authorization` header, which forces a CORS preflight from an
`Origin: null` app — the preflight results above are what make these two providers usable at all.

```js
/*
 * wallpaper.js — where the app's background picture comes from.
 *
 * A tiny provider registry. Each provider is
 *   {id, label, needsKey, fetchRandom(apiKey, deps) -> Promise<{url, credit}>}
 * and `deps` is {client, http, random}. No DOM here: preloading and painting
 * the picture is each shell's job.
 */
(function (root) {
  'use strict';
  var core = root.ImmichCore = root.ImmichCore || {};

  var IMMICH_MAX_PAGE = 20;
  var IMMICH_PAGE_SIZE = 30;

  function failure(code, message) {
    var e = new Error(message);
    e.code = code;
    return e;
  }

  function randomOf(deps) { return (deps && deps.random) || Math.random; }

  function pick(list, random) {
    if (!list || !list.length) { return null; }
    return list[Math.floor(random() * list.length)];
  }

  /*
   * Immich: no key, no third party. Jump to a random page of the library and
   * take a random photo from it; an over-the-end page falls back to page 1,
   * so a small library still works (two requests at worst).
   */
  var immich = {
    id: 'immich',
    label: 'Your Immich photos',
    needsKey: false,
    fetchRandom: function (apiKey, deps) {
      var client = deps && deps.client;
      var random = randomOf(deps);
      var page;
      if (!client) {
        return Promise.reject(failure('no_client', 'No Immich connection for wallpapers.'));
      }
      page = 1 + Math.floor(random() * IMMICH_MAX_PAGE);
      return client.searchPage(page, IMMICH_PAGE_SIZE).then(function (res) {
        var asset = pick(res && res.items, random);
        if (asset) { return asset; }
        return client.searchPage(1, IMMICH_PAGE_SIZE).then(function (first) {
          return pick(first && first.items, random);
        });
      }).then(function (asset) {
        if (!asset) {
          throw failure('empty', 'There are no photos in the library to use as a wallpaper.');
        }
        return { url: client.viewerUrl(asset.id), credit: '' };
      });
    }
  };

  var providers = { immich: immich };
  var providerIds = ['immich'];

  function get(id) {
    return Object.prototype.hasOwnProperty.call(providers, id) ? providers[id] : providers.immich;
  }
  function needsKey(id) { return get(id).needsKey === true; }
  function label(id) { return get(id).label; }

  var api = {
    providers: providers,
    providerIds: providerIds,
    get: get,
    needsKey: needsKey,
    label: label
  };
  core.wallpaper = api;
  if (typeof module !== 'undefined' && module.exports) { module.exports = api; }
}(typeof window !== 'undefined' ? window : global));
```

```js
  /*
   * The one thing the shells call. Never rejects: a failure resolves null so
   * the caller simply keeps whatever picture is already on screen.
   */
  function createWallpaperService(deps) {
    var settings = deps.settings;
    var client = deps.client;
    var http = deps.http;
    var debugLog = deps.debugLog;
    var random = deps.random || Math.random;

    function log(tag, data) { if (debugLog) { debugLog(tag, data); } }

    return {
      refresh: function () {
        var provider, key;
        if (!settings.getWallpaperEnabled()) { return Promise.resolve(null); }
        provider = get(settings.getWallpaperProvider());
        key = settings.getWallpaperKey(provider.id);
        log('wallpaper.refresh', { provider: provider.id, hasKey: !!key });
        return provider.fetchRandom(key, { client: client, http: http, random: random })
          .then(function (res) {
            log('wallpaper.ok', { provider: provider.id, credit: res.credit || '' });
            return res.url;
          }, function (err) {
            log('wallpaper.fail', {
              provider: provider.id,
              code: err.code || '',
              message: err.message
            });
            return null;
          });
      }
    };
  }
```

```js
/*
 * wallpaper.js (legacy shell) — paints the background picture.
 *
 * The picture is loaded with new Image() first and only swapped in once it is
 * decoded, so the screen never flashes; a failed load leaves whatever is on
 * screen alone. backgroundValue() is pure so it can be unit-tested in Node.
 */
(function (root) {
  'use strict';
  var ui = root.ImmichUI = root.ImmichUI || {};

  var OVERLAY = 'linear-gradient(rgba(17, 24, 39, 0.62), rgba(17, 24, 39, 0.62))';

  function backgroundValue(url) {
    if (!url) { return ''; }
    return OVERLAY + ', url("' + String(url).replace(/"/g, '%22') + '")';
  }

  function createWallpaper(targetEl) {
    var token = 0;
    return {
      apply: function (url) {
        var mine = ++token;
        var img;
        if (!url) { return; }
        img = new Image();
        img.onload = function () {
          if (mine !== token) { return; }
          targetEl.style.backgroundImage = backgroundValue(url);
        };
        img.onerror = function () { /* keep the picture that is already there */ };
        img.src = url;
      },
      clear: function () {
        token++;
        targetEl.style.backgroundImage = '';
      }
    };
  }

  var api = { backgroundValue: backgroundValue, createWallpaper: createWallpaper };
  ui.wallpaper = api;
  if (typeof module !== 'undefined' && module.exports) { module.exports = api; }
}(typeof window !== 'undefined' ? window : global));
```

```js
import {useEffect, useRef, useState} from 'react';
import services from './services';

const REFRESH_MS = 600000;	// 10 minutes

/*
 * Returns the wallpaper URL to paint, or null. The picture is decoded with
 * new Image() before it is handed back, so the background never flashes, and
 * a failed fetch or a failed decode simply keeps the previous URL.
 */
const useWallpaper = (active) => {
	const [url, setUrl] = useState(null);
	const token = useRef(0);

	useEffect(() => {
		if (!active || !services.settings.getWallpaperEnabled()) {
			return undefined;
		}
		let stopped = false;
		const load = () => {
			const mine = ++token.current;
			services.wallpaper.refresh().then((next) => {
				if (stopped || !next || mine !== token.current) return;
				const img = new Image();
				img.onload = () => {
					if (!stopped && mine === token.current) setUrl(next);
				};
				img.src = next;
			});
		};
		load();
		const id = setInterval(load, REFRESH_MS);
		return () => {
			stopped = true;
			clearInterval(id);
		};
	}, [active]);

	return url;
};

export default useWallpaper;
```

```markdown
# Wallpaper providers: what was checked, and when

Checked on 2026-09-25 against each service's public documentation and against the
live endpoints with `curl`. `core/wallpaper.js` depends on every line below, so
re-check it here before changing a provider.

## Why CORS decides everything

The packaged app runs from `file://`, so every request it makes carries
`Origin: null`, and both providers below need an `Authorization` header, which
forces the browser to send a CORS preflight (`OPTIONS`) first. A service is only
usable if it answers that preflight *and* allows the `authorization` header.
There is no proxy or relay in this project to work around a service that does not.

## Pexels — usable

- Endpoint: `GET https://api.pexels.com/v1/search?query=nature&orientation=landscape&size=large&per_page=80&page=<1..5>`
- `/v1/curated` exists but takes only `page` and `per_page`, with **no** `orientation`
  parameter, so it cannot guarantee a landscape picture for a 1920x1080 screen.
- Auth header: `Authorization: <your key>` — the raw key, no scheme.
- Response: `{photos: [...], page, per_page, total_results, next_page, prev_page}`.
  Each photo has `id, width, height, url, photographer, photographer_url,
  photographer_id, avg_color, alt, src`.
- Image field used: `src.large2x` — documented as "The image resized `W 940px X H 650px`
  `DPR 2`", i.e. 1880x1300. (`src.landscape` is only 1200x627, too small.)
- Rate limit: 200 requests/hour, 20,000/month. The app refreshes every 10 minutes
  (6 requests/hour), so a free key is ample.
- Free key: https://www.pexels.com/api/
- Live CORS check: `GET` answers `access-control-allow-origin: *`; the preflight
  answers `200` with `access-control-allow-headers: authorization` and
  `access-control-allow-methods: GET, POST, PUT, PATCH, DELETE, OPTIONS, HEAD`.
- Docs: https://www.pexels.com/api/documentation/

## Unsplash — usable

- Endpoint: `GET https://api.unsplash.com/photos/random?orientation=landscape&content_filter=high`
- `orientation` accepts `landscape`, `portrait`, `squarish`.
- With no `count` parameter the response is a **single photo object**; with `count`
  it is an array even for `count=1`. The app omits `count`.
- Auth header: `Authorization: Client-ID <your access key>`.
- Image field used: `urls.raw` plus the documented resize parameters
  `w=1920&h=1080&fit=crop&q=80&fm=jpg`. The docs' "Dynamically resizable images"
  section explicitly supports `w`, `h`, `fit`, `crop`, `q`, `fm`, `dpr` and
  `auto=format` on the `raw` URL. `urls.regular` is only 1080px wide and
  `urls.full` can be a 6000px JPEG, which a 2016 TV should not be asked to decode.
- Credit: `user.name`; the photo page is `links.html`.
- Rate limit: 50 requests/hour in demo mode, 1000/hour once an app is approved.
- Free key: https://unsplash.com/developers
- Live CORS check: `GET` answers `access-control-allow-origin: *`; the preflight
  answers `200` with `access-control-allow-headers: authorization` and
  `access-control-allow-methods: GET, POST, PUT, DELETE, OPTIONS`.
- Docs: https://unsplash.com/documentation

## Wallhaven — researched, NOT usable, future work

`GET https://wallhaven.cc/api/v1/search` answers `HTTP/2 200` but sends **no**
`Access-Control-Allow-Origin` header at all. A browser therefore refuses to hand
the response to a `file://`-origin app, and no API key changes that — it is the
same failure class as an Immich server that has not been configured for CORS.

Wallhaven would need something in the middle that adds the header: a small relay
or proxy. This project has deliberately not got one (the app talks straight to
your own Immich server and nothing else), so Wallhaven stays unimplemented. If a
relay ever exists — the QR-pairing note in the README describes the same missing
piece — adding a `wallhaven` provider to `core/wallpaper.js` is a small change:
the registry is the only place that would need a new entry.

Docs: https://wallhaven.cc/help/api

only goes to the debug log. Showing it on screen is a natural follow-up once the UI
redesign lands; the data is already there.
```

**5. Known, accepted limitations (not bugs)**

- `core/settings.js` validates the provider id against the literal list `immich | pexels | unsplash`
  instead of importing the registry, to keep `settings` dependency-free. Task 1 Step 3 says so and
  both lists must be changed together if a fourth provider is ever added.
- The `credit` string is produced and logged but not shown on screen. Both services ask for
  attribution; `docs/wallpaper-providers.md` records this and flags displaying it as follow-up work
  for the UI redesign (Unit 4).
- The Pexels provider uses a fixed `query=nature`. That is a server-side default, not a filter UI,
  which is what V1 scope allows; a category picker is the natural non-breaking follow-up.
